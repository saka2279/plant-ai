# Plant AI v0.3.0

## 作品概要

Plant AIは、観葉植物「カポック」の状態を複数の観察値から考える、初心者向けの植物管理デモWebアプリです。

表層水分、根元水分、鉢重量変化、温度、湿度を同時に表示し、センサー同士が同じ方向を示しているかを確認します。結果は「乾燥」「水分あり」「湿りすぎ」「判断保留」と、初心者向けの日本語による複数の根拠で表示します。

既存の手入力・デモ判定機能を維持しながら、v0.3.0ではELEGOO UNO R3のシリアル出力から確認したADC生値と、実際のカポックを観察した内容を記録・可視化できます。現在はコンセプトデモと手動転記による実測記録の段階であり、個体別学習は今後カポックの実測データを用いて実装します。

## 独自性

一般的な土壌水分チェッカーは1つの水分値だけで状態を判断します。Plant AIは、表面と根元の水分差、鉢重量の増減、室内環境を照らし合わせ、情報が一致しない場合は無理に結論を出さず「判断保留」と表示します。

特に次の場面を再現できます。

- 表面は乾いていても、根元には水分が残っている
- 表層と根元がともに乾き、鉢重量も大きく減っている
- 水分値だけが急変し、鉢重量は変わっていない
- 水やりによって表層・根元水分と鉢重量が同じ方向へ上昇する

画面の「判断の確からしさ」は、複数センサーの一致度を4段階で表す補助表示です。植物状態の科学的な予測精度や、水やりの正解率を示すものではありません。

## e-ZUKAスマートアプリコンテスト2026

Plant AIは、「第15回e-ZUKAスマートアプリコンテスト2026」の農業分野への応募に向け、飯塚市「統計いいづか2024」と「地域計画」を基に地域課題との関係を整理しています。ADC生値、水やり、土の感触、時系列変化を組み合わせ、初心者が鉢ごとの乾燥傾向と判断理由を学べることを目指します。

現在はカポックを使った鉢植え規模のコンセプト実証（デモと実測記録）であり、機械学習済みAIや農業現場で検証済みの仕組みではありません。事実、分析、仮説、現在の限界、将来展開は[飯塚市の地域課題とPlant AI](docs/ezuka-2026-local-issue.md)に分けて記載しています。

## 現在できること

- 5種類の観察値を手動入力
- 表層・根元水分のスライダーと数値入力を同期
- 複数センサーの一致・一部一致・不一致を判定
- 4種類の状態と4段階の確からしさを表示
- 判断根拠を初心者向けの日本語で複数表示
- 4つの審査用デモシナリオをボタンで再現
- ランダムなデモデータを生成
- 現在の状態をlocalStorageへ記録
- 観察スナップショットを1件ずつ削除
- 保存した観察データをCSV形式で書き出し
- 旧版の単一水分履歴を読み替える互換処理
- スマートフォン向けレイアウト
- ELEGOO UNO R3のA0を20回測定し、平均・最小・最大の生値をUSBシリアルへ約1秒間隔で出力
- センサー未接続、空気中、乾いた土、湿った土の実測結果を同じ条件で記録するための校正シート
- 測定日時、`raw_avg`、`raw_min`、`raw_max`、水やり有無、土の感触、メモを実測記録として保存
- Arduinoのシリアル出力を複数行のまま貼り付け、最新の完全な測定行から`raw_avg`、`raw_min`、`raw_max`を抽出
- 抽出結果を確認してから保存し、貼り付けを使わない場合は3つのraw値を手入力
- 実測記録を新しい順に一覧表示
- `raw_avg`を古い測定から順にグラフ表示
- 水やりありの測定をグラフ上の橙色のひし形で区別
- 実測記録専用CSVの書き出しと読み込み
- 不正CSVや一部の旧形式データを安全に除外

Arduinoの測定値は0〜1023のADC生値です。土壌水分率を表す値ではありません。

## ローカルでの開き方

外部ライブラリやビルド作業は必要ありません。

1. このリポジトリをダウンロードします。
2. フォルダーを展開します。
3. `index.html`をブラウザで開きます。

直接開いたページがブラウザの制限で正常に動かない場合は、このフォルダーで簡易サーバーを起動します。

```bash
python -m http.server 8000
```

その後、ブラウザで次のURLを開きます。

```text
http://localhost:8000
```

## ファイル構成

- `index.html`: 画面構造と日本語表示
- `style.css`: スマートフォン優先の見た目
- `logic.js`: センサー一致度、状態、確からしさ、判断根拠の判定
- `sensor-adapters.js`: `DemoSensorAdapter`と審査用シナリオ
- `script.js`: 入力イベント、画面更新、履歴保存
- `measurement-records.js`: 実測記録の検証、旧形式の読み替え、localStorage、CSV入出力
- `arduino/plant_ai_sensor/plant_ai_sensor.ino`: UNO R3用の平均化測定スケッチ
- `docs/calibration.md`: センサー型番、測定条件、実測値、1分連続測定の記録
- `docs/ezuka-2026-local-issue.md`: 飯塚市の地域課題とPlant AIの位置づけ
- `tests/measurement-records.test.js`: 実測記録とCSV処理の依存なしテスト

判定ロジックは画面更新から分離しています。基準を変更するときは`logic.js`、デモ値を変更するときは`sensor-adapters.js`を確認してください。

## システム構成

現在のWebアプリと実機測定は、どちらも外部APIやクラウドを使わずローカルで動作します。

```text
現在のデモ
DemoSensorAdapter ──→ 判定ロジック ──→ Web画面

Arduinoでの実機測定
土壌水分センサー AO ──→ ELEGOO UNO R3 A0
                              │ 20回平均
                              └─→ USBシリアル ──→ Arduino IDE シリアルモニター

v0.3.0の実測記録
シリアルモニター ──→ 利用者が確認・転記 ──→ 実測記録 ──→ localStorage／グラフ

将来のWeb連携候補
ELEGOO UNO R3 ──→ USBシリアル ──→ SerialSensorAdapter ──→ 判定ロジック ──→ Web画面
```

`sensor-adapters.js`のアダプター境界は維持します。現在の`DemoSensorAdapter`を残したまま、将来`SerialSensorAdapter`を追加して切り替える方針です。v0.3.0ではブラウザからUSBシリアルへ接続する機能は実装せず、確認した値を手動で転記します。

## 実測記録の方法

1. Arduino IDEのシリアルモニターを`115200 baud`で開きます。
2. `uptime_ms=...,raw_avg=...,raw_min=...,raw_max=...,samples=20`の1行を確認します。
3. Web画面の「今回の測定を記録」にシリアル出力を貼り付けます。起動時の説明行や複数の測定行を含めたまま貼り付けると、最新の完全な測定行から3つのraw値を読み取ります。貼り付けを使わない場合は「詳細を手入力」を開きます。
4. 読み取られた`raw_avg`、`raw_min`、`raw_max`と測定日時を確認します。測定日時には現在時刻が入りますが、実際の測定時刻と違う場合は修正します。
5. 水やり有無と土の感触は初期状態で「未確認」です。確認した内容を残す場合だけ変更し、必要に応じてメモを追加します。
6. 「実測記録を保存」を押し、一覧と時系列グラフで前後の変化を確認します。

日時、水やり、土の感触は自動補完しません。`raw_min ≦ raw_avg ≦ raw_max`かつ0〜1023のときだけ登録できます。実測記録は最大500件をブラウザのlocalStorageへ保存し、一覧は新しい順に表示します。デモ観察スナップショットとは別の保存領域です。

## グラフの見方

- 横方向は時間で、左が古く右が新しい測定です。
- 縦方向は`raw_avg`です。表示中の値に合わせて目盛りの範囲が変わります。
- 緑色の丸は通常の測定、橙色のひし形は「水やりあり」と登録した測定です。
- 値が上がると乾燥側か湿潤側かはセンサー製品によって異なります。校正結果と一緒に確認してください。
- raw値だけで水やりを決めず、葉、土、鉢の状態や前後の変化も確認してください。

## 実測CSVの書き出しと読み込み

「実測CSVを書き出す」から、実測記録だけを`plant-ai-actual-measurements-v0.2.1.csv`として保存できます。「実測CSVを読み込む」では、同じ形式のCSVを選びます。

必須列は`測定日時`、`raw_avg`、`raw_min`、`raw_max`です。ID、水やり、土の感触、メモ、データ種別、記録バージョンも書き出します。引用符、カンマ、メモ内の改行に対応し、IDが同じ記録は重複させません。不正な行やデモデータ行は除外し、読み込める実測行がないCSVでは既存記録を変更しません。

デモ観察スナップショットのCSVは別ボタン・別形式です。2種類を同じデータとして混ぜません。

## 主要デモ4種類の動作確認結果

| デモ | 入力・変化 | 確認結果 |
|---|---|---|
| 表面だけ乾燥 | 表層18%、根元58%、重量変化-4g | 「判断保留」「深さで不一致」「低い」 |
| 全体が乾燥 | 表層16%、根元20%、重量変化-86g | 「乾燥」「センサー一致」「高い」 |
| センサー不一致 | 表層水分だけが直前から60ポイント上昇、重量変化-2g | 「判断保留」「センサー不一致」「参考程度」 |
| 水やり変化 | 表層+48ポイント、根元+40ポイント、鉢重量+190g | 水やりによる変化の可能性を表示 |

ここで表示する「確からしさ」は、植物状態の予測精度ではありません。水分値と鉢重量など、現在得られているセンサー情報が同じ方向を示しているかを表す整合性の目安です。

## ELEGOO UNO R3でのセンサー測定

### 使用部品

| 部品 | 数量 | 用途・注意 |
|---|---:|---|
| ELEGOO UNO R3 | 1 | A0でアナログ値を取得 |
| アナログ出力（AO）付き土壌水分センサーモジュール | 1 | 型番と対応電圧を確認してから給電する |
| USBデータケーブル | 1 | 充電専用ではなく、通信対応品を使用 |
| ジャンパーワイヤー | 3 | VCC、GND、AOに使用 |

センサーは製品によって対応電圧、ピン順、値の増減方向が異なります。型番が分からない状態でVCCを接続しないでください。センサー基板の表裏または説明書で仕様を確認し、`docs/calibration.md`へ型番と電圧を記録します。

### 配線

配線はUNO R3からUSBケーブルを抜いた状態で行います。ピンの位置ではなく、センサー基板に印刷された名称を確認してください。

| センサー側 | ELEGOO UNO R3側 | 備考 |
|---|---|---|
| AO | A0 | アナログ出力だけを使用 |
| GND | GND | 共通の基準電位 |
| VCC | 型番で確認した対応電源 | 5Vまたは3.3Vを推測で選ばない |
| DO | 接続しない | v0.3.0ではデジタルしきい値出力を使用しない |

### Arduino IDEでのコンパイルと書き込み

1. Arduino IDE 2を起動します。
2. UNO R3を通信対応USBケーブルでPCへ直接接続します。
3. 「ツール」→「ボード」から「Arduino AVR Boards」→「Arduino Uno」を選びます。
4. 「ツール」→「ポート」から、UNO R3を接続したときに追加されたCOMポートを選びます。
5. `arduino/plant_ai_sensor/plant_ai_sensor.ino`を開きます。
6. 「検証」を押してコンパイルし、「書き込み」を押します。
7. シリアルモニターを開き、速度を`115200 baud`に設定します。

正常時は、約1秒ごとに次の形式で出力されます。

```text
uptime_ms=2000,raw_avg=512.4,raw_min=509,raw_max=516,samples=20
```

この例の数値は出力形式の説明用で、実測結果ではありません。`raw_avg`は20回の平均、`raw_min`と`raw_max`はその20回内の最小・最大です。実測は[校正記録](docs/calibration.md)へ記録します。

### 実機確認状況

2026-07-10にELEGOO UNO R3をArduino UNO（COM6）として認識し、スケッチの書き込みに成功しました。センサー未接続のA0開放状態で65秒間に66行を受信し、`uptime_ms`は1秒間隔で連続していました。`raw_avg`は240.3〜247.8でしたが、開放入力の値なので校正には使用しません。

センサーモジュールの型番と対応電圧が未確認のため、空気中・乾いた土・湿った土の比較は未実施です。型番を確認して安全に配線した後、結果を[校正記録](docs/calibration.md)へ追記します。

### 測定手順

センサー未接続、空気中、乾いた土、湿った土の順に、それぞれ60秒以上測定します。条件を変える前にUSB電源を外し、安全を確認してから配線やセンサー位置を変更します。土の種類、水量、測定開始までの経過時間も記録します。

空気中と湿った土の値に違いが出ることを確認しますが、大小の向きはセンサーモジュールによって異なります。生値をそのまま水分率へ換算したり、特定の値だけで水やりを判断したりしません。

## 今後の実機接続予定

v0.3.0ではUNO R3と土壌水分センサー1本のUSBシリアル測定と、確認した値の手動記録だけを対象にします。BLE、Wi-Fi、Web Serial、ロードセル、温湿度センサーはまだ使用しません。

今後は実測を重ねてセンサーの個体差と土ごとの範囲を確認した後、表層・根元の複数測定、鉢重量、温湿度を段階的に追加します。Webアプリ側では`DemoSensorAdapter`と同じ読み取り形式の`SerialSensorAdapter`を追加し、表示と判定ロジックを保ったままデータ取得部分を切り替える予定です。

外部AI API、クラウド、カメラ診断、自動給水は現在の対象外です。実機接続後も、植物の状態を断定せず、ユーザーが葉や土を確認するための判断材料を提供します。

## GitHub Pagesでの公開予定

すべて相対パスのHTML、CSS、JavaScriptで構成しており、外部APIやサーバー処理を必要としないため、GitHub Pagesで公開できる構成です。現時点では公開前で、今後公開する予定です。

GitHubへリポジトリを送信した後、リポジトリの「Settings」→「Pages」で`main`ブランチのルートを公開元に指定します。CSV出力とlocalStorageはブラウザ内で動作します。

## 注意事項

- 判定基準とデモ値はコンセプト確認用の暫定値です。
- 植物、鉢、土、季節、センサー位置によって適切な値は変わります。
- 実際の葉、土、鉢底、受け皿の状態も確認してください。
- 本アプリの表示だけで水やりを断定しないでください。
- 履歴は現在のブラウザのlocalStorageへ保存され、別端末とは共有されません。
- ブラウザのデータを削除すると、実測記録とデモ履歴も削除されます。必要な記録はCSVへ書き出してください。
- CSV読み込み前には、必要に応じて現在の実測記録をCSVへ書き出してください。

node tests/measurement-records.test.js
